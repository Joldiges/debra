## Decisions agents must not accidentally undo
- Debra is both an affordable, complete Home Assistant voice/music-device pathway and a sourced comparison/reference project. Do not reduce it to one installer or postpone all documentation until software is finished.
- The beginner starts with working Home Assistant and an assembled, prepared Pi. The destination is Wi-Fi onboarding, repeatable hardware-derived identity, then an SSH-accessible setup/maintenance TUI—not a user debugging Linux.
- Full original Pi Zero W support is an engineering goal, not an established capability or an optional music-only downgrade. Pi Zero 2 W is a leading candidate, not a permanent lock-in; a Pi 5 development success does not prove ARMv6 compatibility.
- Prioritize SendSpin initially; keep room for Snapcast and multiple installed stacks. Duck/resume versus pause/resume is a user setting. LVA's internal playback behavior does not prove integration with a separate music receiver.
- Default to pinned components and manual updates; allow explicit per-component auto-update choices. Fast, tested rollback and a post-network/identity baseline are part of the product, not afterthoughts.
- Home Assistant owns most speech/cloud-provider choices. Expose supported device-side options without imposing a new assistant backend or a local/cloud ideology.
- PiCompose is a research/reference candidate, not a chosen foundation. Evaluate partial/information reuse or another approach. Investigate alternative boards (for example selected Orange Pi models) without assuming HAT compatibility or expanding the supported matrix without evidence.

- A capable coordinator owns architecture, task decomposition, and integration; lower-cost models receive narrow assignments, not autonomous project ownership. Editing workers need a recorded clean base, their own branch/worktree, explicit allowed paths, existing check commands, and acceptance criteria. Read-only review may share a checkout when it is not changing.
- The task-chain registry in Git's common directory coordinates one clone's linked worktrees using an atomic lock. Use it for claims, not competing Markdown ownership rows. Self-selection means one prepared starter, not permission for the whole stream; blocked/submitted/failed claims retain ownership until coordinator resolution. Other clones/machines are not coordinated.
- Workers do not merge, push, approve their own work, change tests to hide failures, or edit shared rules/configuration/pins unless explicitly assigned. Missing prerequisites, needed out-of-scope edits, or one unsuccessful repair round are escalation points, not permission to improvise.
- A separate capable review checks the actual diff and evidence; the integrator independently reruns the required checks against the integration result. Only the coordinator integrates within James's authorized scope. Guidance and worktrees are not sandboxes; restrictive worker permissions and review enforcement are not configured or verified yet.
- Preserve durable project findings in dated `docs/notes/` using the [learning-note template](docs/templates/learning-note.md), within assigned file scope. ## What actually exists today
- This checkout has planning/reference docs, historical backup scripts and two prototypes; it is not a working Debra appliance, image, or TUI. `scripts/debra-setup.sh` exists in Git history but is absent from the working tree. The browser slice (`control/web/`) runs, has an installer and has been deployed to the lab device, but the current code candidate is a prototype awaiting acceptance review and is not approved; see [web control](control/web/README.md).
- The first-boot setup service (`control/setup/`) implements device naming from board hardware, a Wi-Fi onboarding portal and a first baseline, with an installer and a system unit; see [setup](control/setup/README.md). Its tests are offline: this code has never raised a radio, joined a network, applied a name or captured a baseline, and no captive portal or access revocation exists.
- One physical lab device exists and runs a voice satellite and a music player: Pi 5 + ReSpeaker 2-Mics v2 with PipeWire, linux-voice-assistant v1.1.18 and the Sendspin 9.1.0 CLI, built by [tools/device/lab-pi5/](tools/device/lab-pi5/README.md). It connects to the household Home Assistant and Music Assistant, and a spoken wake word → speech to text → intent → spoken reply has run end to end. An earlier supply caused undervoltage resets under load; James reports the replacement supply mostly resolved the instability, which is unmeasured. Undervoltage is health information, not itself an instruction to reset. See the [result record](docs/testing/results/2026-11-15-lab-pi5-lva-sendspin.md) and [project brief](docs/project-brief.md) for the current position; the earlier fault evidence is historical.
- `tools/scheduled_runner.py` runs bounded, queued research tasks from a systemd user timer with an optional daily cost cap (`daily_budget_usd` is unset by default, so there is no local cap and spend is enforced at the provider; see [unattended runner](docs/guides/scheduled-runner.md)); its state is git-ignored under `.local/runner/`. `tools/audio_selftest.py` is a device script, not a host test. CAD work lives under `models/`: component envelopes for the Pi 5, three Pi Zero variants, ReSpeaker 2-Mics HAT, three DWEII modules and ten speaker candidates, plus the v17 STEP reference; CAD-only assemblies and printable part designs including a tub-and-lid case have renders in `assets/` folders (see [models/README.md](models/README.md)). Every part is a design, not a print: nothing has been sliced, printed or fit-tested, and no enclosure is a validated design.
- No appliance application build/lint/typecheck/CI configuration is present. Task-dispatch checks from the root: `python tools/taskchain.py check` and `python -B -m unittest discover -s tests -v` (offline Git fixtures retained under `/tmp/opencode/`, no model/permission/hardware proof). `python tools/taskchain.py list` shows shared local claims without creating a registry.
- Opt-in browser checks from the root: `DEBRA_BROWSER_TEST=1 python3 -B -m unittest discover -s tests -p 'test_*browser.py'` (this matches both `test_web_browser.py` and `test_setup_browser.py`). The browser cases require an already-installed Chromium; they use synthetic responses and no device audio.
- Safe historical shell check, from the root: `bash -n backups/backup.sh backups/restore.sh`; focus one file with `bash -n backups/backup.sh`. These are syntax checks only.
- Keep shell scripts LF-terminated (`.gitattributes`). Add actual verification commands here when implementation introduces them; never present proposed commands as existing tooling.
- Do not execute `backups/*.sh` as tests: they use `sudo rsync -aAXv --delete` between `/` and `/mnt/backup/` (restore reverses the direction), omit important paths, and print success unconditionally. They are not a verified snapshot/recovery backend.
