# R04 — reuse existing solutions without preselecting PiCompose

Read R04, the development guide's reuse/provenance rules, and source register.
Start with LVA, PiCompose, pi-gen, and their linked onboarding/recovery solutions.
Research public sources only; no clones outside authorized paths, image builds,
dependency installation, submodule/pin changes, forks, or upstream publication.

## Bounded questions

For those three main projects identify exact inspected revision, license,
maintained architectures, image/runtime roles, audio-board handling,
onboarding/recovery/update policy, resource constraints, and useful components.
For PiCompose compare adoption, partial reuse, reference-only, and another route.

## Acceptance

Return a recommendation per candidate: pinned package/release, source archive,
source-integrated submodule, scoped patch/fork, or documentation-only. Separate
upstream facts, assumptions, gaps, and proposed architecture. Explain source
initialization, tests, provenance, maintenance/upstream exit, and rollback needs
for each proposed actual reuse. Do not select the shared architecture or silently
make PiCompose a dependency.
