# B01 — recoverable Pi state without inventing a backup product

Read B01, the brief's recovery goals, and legacy hazards. Research upstream
filesystem/backup documentation. Never execute `backups/*.sh`, mount media,
snapshot/restore host files, install tools, or operate devices.

## Bounded questions

Compare at least one CoW and one incremental non-CoW approach for realistic
separate boot/root Pi layouts. Examine consistent capture, boot/kernel/modules
coupling, live versus offline restore, storage overhead/minimum card, full-disk
and power-loss failure, credential protection, and unbootable-root/dead-card rescue.

## Acceptance

Give a source-backed decision table and minimal first-backend recommendation
plus exit path, not a selected implementation. Separate same-card rollback,
off-device backup, and rescue/reflash. State a future disposable-media restoration
test that proves networking/SSH/identity/boot coherence and measures time.
Do not claim backup success or permission for a destructive trial.
