## 16:0x — Code review: four state-machine defects, one restructure

WEB-REVIEW-04 accepted the rejection-persistence fix and found four more defects
in the browser state machine. All four came from one cause: a single `notice`
string and a single `unconfirmed` flag for two independent controls.

1. **HTTP 503 was treated as proof that nothing was applied.** The server returns
   503 when audio control is unavailable, including when a native command timed
   out *after* it may have run. The page said "not applied" and kept the error.
2. **A successful mute erased a volume rejection**, and a successful mute cleared
   volume uncertainty — unrelated evidence destroyed by an unrelated success.
3. **A pending write kept the pre-submission "not applied" label**, and an
   unavailable readback left it there indefinitely.
4. **Reconciling an old request discarded a newer preview**: submit 24 %, lose the
   response, move the slider to 50 %, and the next read of 24 % replaced the 50 %
   preview.

The fix is a restructure rather than four patches: `volumeOp` and `muteOp` are
separate records, each `pending`, `uncertain` or `rejected` with its own message;
`draft` now means only "the slider holds an unsubmitted value"; a definite
refusal is an HTTP status in a small set (400/401/403/404/405/413) and everything
else — including 503 and no answer — is uncertain until a readback agrees with it.
Reconciliation clears the draft only if the slider still equals what was
submitted.

## 17:0x — The hub can find Debra devices over mDNS

`127.0.0.1:8787` only knew about devices someone typed into `.local/devices.json`.
A device that exists on the LAN but is not in that file is invisible, which is
the wrong way round for something whose whole point is "one page for every
Debra".

**The device advertises.** A `debra-advertise` user unit runs
`avahi-publish-service` for `_debra._tcp` on port 8787 with `name` and `label`
TXT records. It is active on the lab Pi (`debra-3c6b3f`, label "Lab Pi 5"),
starts at boot through the existing linger, and is one `systemctl --user
disable --now` away from gone.

**The hub browses.** `tools/discover.py` runs `avahi-browse -rtp -t
_debra._tcp`, parses the resolved records, merges the same service seen on two
interfaces into one entry, and returns the record shape the browser already
uses (`name`, `url`, `label`). It accepts only a `.local` host and a port in
1..65535, so a hostile announcement cannot hand the page a link it would not
have accepted from the configured list. A missing `avahi-browse`, a stopped
daemon or a timeout returns a reason, never an exception: discovery is a
convenience and the configured list still works without it.

Verified end to end: the browse from the host returns `debra-3c6b3f · Lab Pi 5 ·
http://debra-3c6b3f.local:8787/ · 192.168.0.8`. Ten offline tests cover the
parser, the interface merge, the rejected announcements and the failure paths.

Still to do: the dashboard does not yet merge the discovered list into
`/api/devices`; that change waits for the code-r5 fix round so two editors are
not in `server.py` at once.
